# SimEx: instructions for coding agents

SimEx is a personal research tool for testing the owner's own AI traders against a live market:
live Gemini market data, simulated money, honest fills (ADR 0010).

**Read [`.github/copilot-instructions.md`](.github/copilot-instructions.md) before starting work.**
It holds the full context: what exists today, every measured constant with the ADR that owns its
distribution, the workflow, and the environment notes. This file exists because not every agent
reads that path; the hard rules below are repeated here so they are never missed.

## Hard rules

- **Money is `Decimal`, never float**, in the ledger, matching engine, fees and balances
  (ADR 0004). Serialize decimals as strings.
- **Simulation only.** Never add code that places real orders or moves real money (ADR 0002).
- **Only the ingestor talks to an exchange.** Every other component reads from Kafka and must not
  depend on which venue the data came from.
- **Personal use only (ADR 0010).** No public leaderboard, public sign-up, downloadable recordings,
  or public page showing market data or results derived from it. Any web UI is private.
- **Never commit market data**: no recordings, feed dumps or fixtures copied from a live feed. Test
  fixtures are hand-written or synthetic. `data/` and `*.parquet` are gitignored.
- **Coinbase data never feeds agents, the matching engine or scoring.** Coinbase's terms forbid
  using its data to benchmark AI agents. The Coinbase adapter is off by default, is for feed
  research only, and publishes to `research.coinbase.md.*`.
- **One writer per trading pair for books and matching.** Balances are owned by a per-account
  writer (ADR 0014): cash is shared across pairs, so it is the one deliberate exception. Pair
  engines never touch balances; they report fills to the account writer. No other shared mutable
  state across pairs. Don't fold the account writer into the pair engines.
- **Never commit secrets**: no `.env`, keys (`*.key`, `*.pem`), tokens or passwords. Use
  `.env.example` for placeholders.
- **No AI attribution** anywhere: no `Co-Authored-By` trailers, no "Generated with" or
  "Generated by" footers in commit messages, PR descriptions, issues or issue comments. If a tool
  appends one, remove it before the work is considered done.
- **Commits are authored by the owner**, `Abhitej S <suddhaabhitej@gmail.com>`, never by an AI
  tool. Check `git config user.email` before the first commit of a session; a SessionStart hook in
  `.claude/settings.json` sets it.

## Workflow, in short

- Never commit to `main`. Branch as `<type>/<short-name>` and open a pull request.
- Always `git checkout main && git pull` before creating a branch.
- Reference the issue in the PR (`Closes #N`), one issue per PR.
- Before opening a PR run `ruff check .`, `ruff format --check .` and `pytest`; all must pass.
  Postgres-backed tests need `SIMEX_TEST_POSTGRES_DSN` and `SIMEX_REQUIRE_POSTGRES_TESTS=1`, or
  they skip silently and the run means nothing.
- A significant design choice gets an ADR in `docs/adr/` and a row in `docs/adr/README.md`.
- Propose the design on the issue before building anything non-trivial.
- If a task is ambiguous, ask before building.

`CLAUDE.md`, `.github/copilot-instructions.md` and this file carry the same hard rules. Change
them together.
